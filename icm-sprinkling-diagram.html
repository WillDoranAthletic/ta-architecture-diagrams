Processing order

Middle
→
High-middle
→
End
Why this order: middle runs first because it has the strictest position constraints. High-middle runs second and depends on dropzoneCount ≥ 1 being true (satisfied by the ad pass, not by prior ICMs). End runs last.

Placement rules

  • Never within ADS_MIN_PARAGRAPH_CHAR_LENGTH of an embed or ad Keeps visual weight balanced
  • Never directly before an image Avoids awkward caption stacking
  • Never directly after a header Header → paragraph reading flow stays intact
  • Never in the first ⅓ of the article Let the reader into the piece first
  • Prefer directly before a header (if headers exist) Visually clean break
  • Otherwise, between paragraphs Fallback when no headers present
  • ≤ 2 paragraphs remaining after insertion point Too close to the end; skip

Storytelling guards

  • Middle — skipped if containsStorytelling No override available
  • High-middle — skipped if containsStorytelling No override available
  • End — skipped unless overrideStorytelling = true Or the storytelling flavor's enable flag is false

Pickem exception

Pickem has graphicId === null. It skips buildGraphicsModule and emits a client-hydrated placeholder: <p id="article-pickem"></p>.
Entry point: sprinkleInContentModules in apollo/src/helpers/graphics.ts · Runs after ad sprinkling, before HTML assembly · Device-agnostic (surrounding dropzone layout differs, logic does not)

3. Pitch-integration gaps — where new plumbing is required

Every data source each pipeline reads assumes WordPress owns the article. For Pitch-authored articles (Scoop UUIDs, no WP row) to be eligible for daily or weekly digest ranking, these specific plumbing pieces need to be added. See the Newsletter data access and Pitch integration Coda page for the full analysis.

# Gap What's missing Required change
1Article existencePitch articles have no row in ebdb.posts (Redshift) or posts (WP MySQL)Scoop article registry replicated into Redshift and/or WP MySQL as a compat table
2Tag relationshipspost_team, post_league, post_author, post_city have no rows for PitchPitch tags flow into the same (or UNIONed parallel) tables — drives follow-based audience matching
3Read-state trackinguser_articles_read.article_id is INT, keyed on WP post_idRead-tracking pipeline accepts UUIDs; schema widens OR parallel user_pitch_articles_read table added
4ID namespaceEvery query assumes INT post_id; Scoop UUIDs are stringsOne of: (a) synthetic INT bridge per UUID, (b) widen post_id to VARCHAR, (c) UNIONed mixed-type queries
5Feature engineeringdatamart.content_stats, post_stats, user_all_topic_views_rolling are WP-post-id-keyed; CatBoost was trained on WP-article featuresRetrain with Pitch articles OR provide imputed default features for cold-start
6Datamart handoff tabledatamart.digest_daily_articles_us sync from Redshift → WP MySQL assumes WP post_idsConfirm the DE-owned sync tolerates Pitch IDs (depends on Gap 4 choice)
7Push Tool V3 article lookupWP Push Tool V3's get_view_post_data queries posts/wp_posts — cannot resolve Scoop UUIDsNew push-composition wizard in Pitch that reads from Scoop (NOT a port of V3)
